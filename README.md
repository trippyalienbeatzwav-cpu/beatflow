# TUNIBEAT: music marketplace and social network

TUNIBEAT is one platform with three areas that share an account system:

- **Beats Store** (`#/beats`) for producers' beats and packs.
- **Electronic Music Store** (`#/electronic`) for tracks and releases. It has a DJ preview player with frequency-coloured waveforms analysed from the real audio. See [docs/PLAYER.md](docs/PLAYER.md).
- **TUNIBEAT Social** (`#/social`), a separate social network: feed, posts, reels, stories, live streaming with chat and gifts, DMs, notifications, a credits wallet, creator earnings and withdrawals, moderation and admin. See [docs/SOCIAL.md](docs/SOCIAL.md).

Everything runs on a real backend (Node + SQLite): accounts with email verification, carts and checkout priced on the server, sandbox payments with signed webhooks, entitlements, signed download links, seller uploads analysed on the server, and a double-entry-style ledger. Architecture, data model and API: [docs/BACKEND.md](docs/BACKEND.md).

All seeded content is fictional and original. Cover art and avatars are generated. The seeded catalog's audio is synthesised from its metadata and run through the same ingest as uploads; anything a seller uploads is real audio. Social seed media is generated by `npm run seed:media`.

## Run it

Needs **Node 22.13+** (uses the built-in `node:sqlite`) and, for end-to-end tests and ingest, Microsoft Edge or Chrome.

```bash
npm install
cp .env.example .env # optional in development; required values for production are marked there
npm start            # http://localhost:5173 — seeds a development database on first run
```

Production: `NODE_ENV=production DOWNLOAD_SECRET=… COOKIE_SECURE=true PAYMENTS_PROVIDER=stripe STRIPE_SECRET_KEY=… STRIPE_WEBHOOK_SECRET=… WEB_ROOT=dist node --env-file=.env server/index.js` behind an HTTPS reverse proxy. Dev tools (demo sign-in, mail outbox, sandbox payments) are off in production.

| Script | What it does |
|---|---|
| `npm start` / `npm run dev` | Start the server (dev restarts on server changes) |
| `npm run seed` | Reset and reseed the development database |
| `npm run seed:media` | Regenerate the social seed images and videos (headless browser) |
| `node scripts/render-catalog.mjs` | Re-run the Electronic catalog ingest: render, analyse, encode previews and waveforms |
| `npm run lint` · `npm run typecheck` | ESLint (whole repo) · TypeScript `checkJs` over the server and API tests |
| `npm test` | Unit and API tests (DSP, money, social, real-time, auth, store commerce/downloads/refunds/uploads, collections) |
| `npm run test:e2e` | Browser tests: buyer journey (sign up → verify → play → playlist → checkout → download), DJ player, Player Lab, social flows, responsive layouts, the production build |
| `npm run build` | Bundle to `dist/` (hashed JS and CSS). Serve it with `WEB_ROOT=dist npm start` |
| `npm run test:all` | Everything above, in order |

`serve.ps1` still serves the static stores for a quick look, but Social and the preview audio need the Node server.

## Deploy: Vercel (front end) + Render (server)

Vercel serves the static site (`npm run build` → `dist/`, configured in `vercel.json`). It can't run the Node server (SQLite on disk, uploads, WebSockets, audio workers), so that runs on Render and Vercel forwards `/api` and `/media` to it (`middleware.js`). The browser stays on your Vercel domain, so cookies and CSRF work unchanged; live features open a WebSocket straight to Render with a one-time ticket.

1. **Render** → New → **Blueprint** → this repository. `render.yaml` creates `beatflow-api` (Node 24, 5 GB disk at `/var/data`, health check `/api/health`, generated `DOWNLOAD_SECRET`). Fill in:
   - `PROXY_SECRET`: 24+ random characters (you'll paste the same value into Vercel)
   - `PUBLIC_URL`: your Vercel URL, e.g. `https://beatflow-blond.vercel.app`
   - `RESEND_API_KEY` and `MAIL_FROM`: needed for sign-up verification codes and password resets
   Disks need a paid instance (the blueprint uses `starter`). Note the service URL, e.g. `https://beatflow-api.onrender.com`.
2. **Vercel** → Project → Settings → Environment Variables (Production):
   - `API_ORIGIN` = the Render URL from step 1
   - `PROXY_SECRET` = the same value as on Render
   Then **Redeploy**. Until `API_ORIGIN` is set, `/api` answers `503 api_not_configured`.
3. Check: `https://<your-vercel-domain>/api/health` returns `"ok": true` and `"via_proxy": true`.

Card payments stay off until `PAYMENTS_PROVIDER=stripe` and the Stripe keys are set on Render; the catalog, previews, accounts and Social work without them. The demo catalog is seeded on first start (`SEED_DEMO=false` for an empty store); demo purchases are only seeded with the sandbox provider, so production never gets fake orders.

## Two separate stores, one platform

TUNIBEAT runs two marketplaces that are completely separate. The platform home (`#/`) asks *What are you looking for?* and sends visitors to one of them. Each store has its own navigation, identity and vocabulary, and products never appear in the other store.

| | Beats Store `#/beats` | Electronic Music Store `#/electronic` |
|---|---|---|
| Sells | Beats, instrumentals, stems, samples, loops, packs | Tracks, singles, EPs, albums, remixes, compilations, DJ tools |
| Buying model | License: Basic / Premium / Trackout / Exclusive | Download: track or full release, WAV / AIFF / MP3 |
| Words | Buy Beat, License, Producer, Stems, Trackout, Exclusive | Buy Track, Buy Release, Artist, Label, EP, Album, Catalog, Download |
| Nav | Home · Discover · Beats · Producers · Genres · Charts · Library | Home · Discover · New Releases · Genres · Artists · Labels · Charts · Library |
| Look | Warm charcoal, purple, warm gradients, studio | Black / graphite, electric blue, cyan, record store |
| Orders | `TBB-…` | `TBE-…` |

**Shared:** one account and session, one cart and payment, the player, the seller dashboard and verification. A mixed checkout makes **one payment and one order per store**. The cart and the success screen show each order separately.

**Separation is enforced on the server.** Every product, order and payout row carries its marketplace. The quote/checkout service rejects licenses on electronic items and formats on beats, splits one payment into one order per store, and search groups results by store. The client mirrors these rules only for immediate feedback.

**Search** is scoped to the current store. The overlay and results page offer an explicit *Search both marketplaces* option, which shows the stores in separate groups, never interleaved. The store switcher in each store header is deliberately subtle. The router derives the store from the URL prefix and sets `body[data-eco]`. Store identities are CSS tokens scoped to `[data-eco="beats"|"electronic"]`, so components never branch on the store.

**Ranked vs. curated.** Charts are ordered by downloads only. They show a CHART pill, a solid rule, condensed numerals and movement arrows. Editorial collections always name their curator, use a dashed rule and a cyan edge, and never show a number.

**Electronic demo tips:** search `124 BPM melodic techno`, `8A deep house`, or a catalog number like `VS042`. Turn on *Harmonic mix with* in the Key filter. Toggle **DJ · From drop** in the player so previews start at the drop cue. Add two tracks from an EP, then **Buy release**: the singles are replaced by the full release. Admins can hide, rename, reorder and add genres in **Dashboard → Genres (admin)**; changes are stored on the server and apply to every visitor.

## Design system: “Signal & Flow”

- **Surfaces.** Near-black `#0a0a0c` with four raised steps. Borders carry the elevation, not heavy shadows.
- **Accent.** Violet `#7b4dff` (white text 4.8:1) for actions, `#a98bff` for accent text (7.1:1). Cyan is kept for verification and info.
- **One gradient.** Violet to cyan (`--flow`), used only for playback/upload progress and the brand mark.
- **Type.** Archivo at 118% width, uppercase, for display headings. Inter for body text. JetBrains Mono for musical metadata (BPM, key, time), prices and order IDs.
- **Shape.** Tight radii (3/5/8/12px) so it reads as hardware, not bubblegum. 4px spacing base.
- **Motion.** 120/180/320ms, all zeroed under `prefers-reduced-motion`.
- **Charts.** One axis per chart, 2px lines, 4px rounded bar ends. Categorical slots come from a validated colorblind-safe dark palette, and every chart has a legend, labels or a table view.
